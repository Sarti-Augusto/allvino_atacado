# Plan 01-01: Autenticação & Segurança

## Goal
Implementar o fluxo de autenticação administrativo para o Allvino B2B, incluindo middleware de proteção, ações de login/logout e views administrativas básicas.

## Requirements
- AUTH-01
- AUTH-02
- AUTH-03

<task id="01-01-01">
  <title>Criar Middleware de Autenticação do Supabase</title>
  <read_first>
    - .planning/phases/01-autenticacao-e-seguranca/01-CONTEXT.md
    - src/lib/supabase.ts
  </read_first>
  <action>
    Criar o arquivo `src/middleware.ts` utilizando a biblioteca `@supabase/ssr`.
    O middleware deve:
    1. Instanciar o cliente Supabase utilizando `createServerClient` com os cookies do Next.js.
    2. Atualizar o token de sessão do usuário invocando `supabase.auth.getUser()`.
    3. Interceptar todas as rotas sob `/admin/*` (exceto `/admin/login`).
    4. Se não houver sessão ativa, redirecionar o usuário para `/admin/login`.
    5. Se houver sessão ativa e o caminho for `/admin/login`, redirecionar o usuário para `/admin`.
    Utilizar o matcher: `matcher: ['/admin/:path*']`.
  </action>
  <acceptance_criteria>
    - O arquivo `src/middleware.ts` existe.
    - O matcher do middleware inclui `/admin/:path*`.
    - Contém chamadas para `createServerClient` e `supabase.auth.getUser()`.
  </acceptance_criteria>
</task>

  </acceptance_criteria>
</task>

    Criar o arquivo `src/app/admin/layout.tsx`.

    2. Obter o usuário atual com `supabase.auth.getUser()`. Se não houver usuário, chamar `redirect('/admin/login')`.
    3. Fazer uma query na tabela `public.admin_users` filtrando pelo ID do usuário: `supabase.from('admin_users').select('ativo, role').eq('id', user.id).single()`.
    4. Se o perfil não for encontrado ou se `ativo` for `false`, chamar `redirect('/admin/login')` (após efetuar signout para limpar a sessão inválida).
    5. Renderizar o layout envolvendo o `{children}` com um container estrutural de estilo básico.
  </action>
